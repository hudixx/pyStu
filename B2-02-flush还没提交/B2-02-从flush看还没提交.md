# 选修 B2 第 2 课：从 flush 看还没提交

`flush` 把 INSERT 发到当前这条连接上。`commit` 之后，别的会话才能看见。

运行：

```bash
PYTHONUTF8=1 python B2-02-flush还没提交/02_flush.py
```

应看到：

```text
flush 后同一个会话 1
flush 后别的会话 0
commit 后别的会话 1
```

跑完不会在目录里留下 db 文件。

---

## 1. 两个动作

| 这一课 | 同一个会话 | 别的会话 | Java |
|---|---|---|---|
| `flush` | 查得到 | 还是 0 | `em.flush()`，事务还没提交 |
| `commit` | 查得到 | 变成 1 | 事务提交 |

同一个会话看得到，是因为它自己的事务里已经有这行。不是因为库已经对所有人提交了。

第 53 课把 `commit` 放在请求结束，路由里只 `flush`，就是为了这个边界。路由中间提前 `commit`，后面失败就收不回这一行。

内存库不适合这课的「另一条连接」。`sqlite:///:memory:` 往往每条连接各有一块空库。示例用临时文件，并且打开 WAL，这样读不会被还没提交的写锁住。

---

## 本课肌肉记忆

1. `flush` 不是 `commit`
2. 同一个会话能看见，不代表别的会话能看见
3. 别的会话要等提交
