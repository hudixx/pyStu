# 选修 B2 第 3 课：从 N+1 看循环里的查询

先查出 N 个用户，循环里再点每个用户的订单。默认会再查 N 次。这就是 N+1。

运行：

```bash
PYTHONUTF8=1 python B2-03-一次变多次/03_多次查询.py
```

应看到：

```text
不预加载 3
预加载 2
```

这里 N 是 2。1 条查出用户，再加 2 条订单，一共 3。预加载是 2：用户一条，订单用 `IN` 再一条。

---

## 1. 点到才查

`relationship` 不写 `lazy`，集合默认是 `select`。对照 `@OneToMany(fetch = LAZY)`。

`user.orders` 看起来像一个已经在手里的 list。第一次点它，才会发 SQL。循环两个用户，就发两次。

`selectinload` 只作用于这一次查询。它不把关系改成永远预加载。对照这次查询上的 `JOIN FETCH` 或 `@EntityGraph`，不是改映射上的默认值。

用户少的时候，多出来的查询不明显。列表一页 50 个，每个再查订单，就是 51 条。慢在往返次数，不在 ORM 这个名字。

---

## 本课肌肉记忆

1. 循环里点关系，先数 SELECT
2. 默认集合是点到才查
3. `selectinload` 是这一次查询的加载，不是改默认
