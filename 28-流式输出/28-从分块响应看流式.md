# 第 28 课：从分块响应看流式

真模型生成要几秒。等完整 body 再返回，前端就对着白屏。流式是 **边生成边推**，对标分块 HTTP / SSE，不是 WebSocket 必修。

运行：

```bash
PYTHONUTF8=1 python 28-流式输出/28_流式.py
```

假模型会按字符往外推，你应看到字一个一个出来，最后有一行完整拼接。

---

## 1. SDK 怎么开

```python
stream = await client.chat.completions.create(
    model="mock-chat",
    messages=[{"role": "user", "content": "你好, hudi"}],
    stream=True,
)
parts: list[str] = []
async for chunk in stream:
    delta = chunk.choices[0].delta.content
    if not delta:
        continue          # 首包常只有 role，尾包只有 finish_reason
    print(delta, end="", flush=True)
    parts.append(delta)
print()
print("拼接 =", "".join(parts))
```

和 `stream=False` 的差别：

| | 非流式 | 流式 |
|---|---|---|
| 返回值 | 一个 `ChatCompletion` | 异步迭代器 |
| 文本在哪 | `choices[0].message.content` | `choices[0].delta.content`（可能 `None`） |
| 何时结束 | `await create` 返回 | 迭代耗尽；服务端会发 `data: [DONE]` |
| usage | 一般在最终对象上 | 有的网关在最后一块，有的要另开开关 |

对照 Java：`BodyHandlers.ofLines()` 读 SSE；不是等 `BodyHandlers.ofString()`。

---

## 2. 协议叫 SSE

HTTP 响应 `Content-Type: text/event-stream`，每块一行：

```text
data: {"choices":[{"delta":{"content":"回"}}]}

data: [DONE]
```

SDK 已经帮你拆好。自己用 httpx 也能读，但作业用 SDK，别手写解析。

下一课的 FastAPI 接口若要推给浏览器，可以：

- 再包一层 SSE 给前端
- 或 `StreamingResponse` 直接吐纯文本

第 31 课用第二种，少一层概念。

---

## 3. 失败发生在中途

流式可能已经推了半句然后 断连 / 超时 / 内容过滤。前端要能停，服务端 `async for` 要用 `try/finally` 关客户端。
本课假模型不会中途炸。第 30 课再练超时。

## 本课肌肉记忆

1. `stream=True` + `async for chunk`
2. 取 `delta.content`，判断 `None`
3. 用户看到的「一个字一个字」来自多块 HTTP，不是 WebSocket 才能做
4. 拼接才是完整答案；不要假设每一块都是一个词
