# 第 56 课：从事件循环看阻塞

`async def` 不会把里面的 `time.sleep` 变成异步。那一行占住事件循环，别的任务进不来。

运行：

```bash
PYTHONUTF8=1 python 56-不要堵住事件循环/56_事件循环.py
```

堵住的那一对大约 `0.40` 秒。让出的那一对大约 `0.20` 秒。机器忙时会有零点几秒的偏差。健康检查打印 `ok`。

---

## 1. 模型调用是 IO

等待模型返回时，线程本来可以去干别的请求。用 `asyncio` 的等待，或者把同步客户端丢进线程池。不要在 `async def` 里直接 `time.sleep`，也不要在里面直接调用同步的 HTTP 客户端。

16 个同步 worker 空等模型，是 16 个线程都堵在 IO 上。并发上不去，机器倒是占满了。

---

## 2. 部署和推理，本课只认边界

同目录的 `Dockerfile` 只给看，不必构建。健康检查回答进程还在，不在里面打模型、不查整库。密钥不放进镜像。

vLLM 是另一台机器上的推理服务。上下文长度、批大小、量化，都是容量参数，对照 JVM 堆大小。你的服务通过 HTTP 调用它。这一阶段不训练模型，也不要求有 GPU。

## 本课肌肉记忆

1. `async def` 里用 `await asyncio.sleep`，不用 `time.sleep`
2. 健康检查不打模型
3. vLLM 是容量，不是训练
