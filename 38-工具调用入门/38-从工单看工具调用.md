# 第 38 课：从工单看工具调用

模型不会执行你的函数。它只返回一张工单：工具名，加上一段 **字符串** 形式的参数。你的代码决定跑不跑、怎么跑。

运行：

```bash
PYTHONUTF8=1 python 38-工具调用入门/38_工具.py
```

「列出待办」应看到工具名 `list_todos`、`arguments` 是 `{}`、`content` 是 `None`。
「你好」没有 `tool_calls`，正文是回声。

本阶段用 `38-工具调用入门/mock_tools.py`。不要用第 26 课的 `mock_llm.py`，那个不会返回工具调用。

---

## 1. 工单不是执行

```text
你把 tools 说明书和用户的话发给模型
模型返回 tool_calls（名字 + arguments 字符串 + id）
你的 Python 函数才执行
执行结果用 role=tool 再喂回去
模型这才写给人看的正文
```

对照：用户在页面上点了「创建订单」，网关收到的是一份 DTO，不是已经写进数据库的行。谁把模型的话当成已经删了库，谁就把未提交的工单当成了 commit。

`arguments` 是字符串，因为协议里它就是一段 JSON 文本。要变成 dict，得你自己 `json.loads`。loads 可能失败，第 39 课管这个。

---

## 2. 说明书必须跟这次请求走

`tools=` 是这次 HTTP 的字段，告诉模型允许点哪些函数。没传，假模型一律回声，`TOOL:` 开头的句子也不会变出工单。

对照：没在接口文档里暴露的方法，调用方就不该点到。暴露了也不等于有权限执行。

---

## 本课肌肉记忆

1. `tool_calls` 是工单，`content is None` 是正常的
2. `arguments` 先当字符串看
3. 本课的假模型是 `mock_tools.py`，端口由系统分配，不占 8001
