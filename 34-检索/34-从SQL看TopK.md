# 第 34 课：从 SQL 看 Top-K

有了块和向量，检索就是：问题也变成向量，和库里每一块算余弦，取得分最高的几块。不是 `SELECT *` 把手册全返回。

运行：

```bash
PYTHONUTF8=1 python 34-检索/34_检索.py
```

三问应分别落到「退款」「客服」「订单号」。

---

## 1. 内存列表就是最小的向量库

```text
index = [(chunk, embed(chunk.text)), ...]
```

用户来问时只 `embed(question)` 一次，再和库里的向量比。对照：插入文档时建索引，不是每次查询全表扫描原文去调模型。

生产可以换成 **pgvector**（Postgres 里的向量列）或一个专用向量库。查询仍是「给我最像的 k 条」。业务上的用户、订单仍是普通 SQL 表，不要把待办存进向量库。

本课不上数据库。阶段十才学表。现在装 Postgres 会把 RAG 挡住。

---

## 2. Top-K，外加一条关键词

`k=2` 表示最多拿两块去拼提示词。k 太大又回到「把半本手册塞进去」。

向量对「退款几天」这种换说法更有用。订单号 `SKU-8891`、电话号码这种必须原样出现，关键词更稳：问题里有这段编号，且正文里也有，就优先。

这就是混合检索的最小版：

| 问法 | 更稳的那一路 |
|---|---|
| 几天能退、怎么退款 | 向量 |
| 完整订单号、完整电话 | 关键词 |

不要二选一当信仰。编号用关键词，语义用向量。

---

## 本课肌肉记忆

1. 入库时算向量，查询时只算问题的向量
2. 取得分最高的 k 块，不要全返回
3. 精确编号用关键词兜底
4. 向量库不是业务数据库
