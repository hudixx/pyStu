# 第 45 课：从验收看裁判模型

请另一个模型给回答打分，叫 LLM-as-judge。能用，不能当唯一的验收。裁判和被评的是同一种东西，都会漏、都会顺着好话给过。

运行：

```bash
PYTHONUTF8=1 python 45-裁判也会错/45_裁判.py
```

「有要点」：规则和裁判都是过。
「没要点但吹捧」：规则不过，裁判过。发布门槛如果只看裁判，这题会绿灯。

本课的 `judge` 是写死的函数，方便断言。真环境它是**另一次** `chat.completions.create`，又一份 token，又一次会错的调用。

---

## 1. 裁判放在规则旁边，不替换规则

```text
退款天数、电话、拒答     规则。不过就不能上。
语气、是否跑题、长文摘要  可以让裁判看。抽查，人仍要看一眼。
```

对照：CI 里测试红了，不能因为静态扫描说「代码质量高」就合并。扫描是辅助。

裁判的提示词里写「请严格」，挡不住它讨好。和第 40 课一样：上限写在代码里，不写在请它自觉的那句话里。

## 本课肌肉记忆

1. 关键要点用规则
2. 裁判和规则不一致时，信规则
3. 裁判自己也是一次模型调用，会错，还要钱
