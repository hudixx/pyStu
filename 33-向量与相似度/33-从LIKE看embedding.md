# 第 33 课：从 LIKE 看 embedding

切块之后，要回答「哪一块和这个问题最像」。`LIKE '%退款%'` 只能对上同样的字。用户问「几天能退」，正文写的是「7 天内可以退款」，关键词可能对不上。

embedding 把一段文字变成一串数字（向量）。像的句子，方向接近。

运行：

```bash
PYTHONUTF8=1 python 33-向量与相似度/33_向量.py
```

应看到：退款问题更接近退款段落，而不是价格段落；一段和自己的相似度是 1.0。

---

## 1. 这课的向量是假的

真环境是：

```python
resp = await client.embeddings.create(model="text-embedding-3-small", input=text)
vector = resp.data[0].embedding  # list[float]
```

各家名字不同，和 chat 的 `model` 一样，看网关文档。**不要**把 chat 模型名拿去算 embedding。

本课 `embed()` 用关键词加字二元组造一个 32 维向量，方便你断言、不花钱。换真模型时只换这一个函数，后面的余弦、检索不用改。

不要用内置 `hash()`。它每次启动进程会变，同一句话两次向量不同，库就废了。

---

## 2. 余弦相似度不是 LIKE

```text
cosine = 点积 / (两个向量的长度)
```

| | LIKE | 余弦 |
|---|---|---|
| 比什么 | 是不是含这段字符 | 方向像不像 |
| 「退款」和「几天能退」 | 常常对不上 | 共享「退款」相关维时会接近 |
| 结果 | 真/假 | 一个小数，越大越像 |

1.0 表示方向相同。0 表示正交，几乎无关。

## 本课肌肉记忆

1. embedding 的产物是 `list[float]`，不是一段更短的摘要
2. 用余弦比大小，不要用 `==`
3. 本课向量是教学替身；真向量来自 embedding 接口
4. 向量必须稳定，不能用会变的 `hash()`
