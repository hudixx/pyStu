# 选修 B4 第 2 课：从 CacheEvict 看失效

改了库，如果缓存键还在，下一次读不会去库里看。要删掉这个键。对照 `@CacheEvict`，不是把新值再 `set` 进缓存。

库用一个字典代替。这课不写 SQL。

运行：

```bash
PYTHONUTF8=1 python B4-02-改完就删掉/02_失效.py
```

应看到：

```text
先读 买牛奶
忘记删除再读 买牛奶
删掉再读 买面包
```

中间那一行是故意不删。库已经是「买面包」，缓存里还是「买牛奶」。

---

## 1. 先改库，再删键

`read_title` 先 `get`。是 `None` 才读库，然后 `set`，并带上 `ex=60`。60 是秒，到点键自己没了。这是忘记删除时的兜底，不是这次更新的办法。

`change_title` 先改字典，再 `delete`。不要在这里 `set` 新标题。

两个请求可能这样叠在一起：甲读到旧标题，乙已经改完库并删了键，甲再把刚才读到的旧标题 `set` 回去。删除不会把旧值写回去。下一次谁读，都再问库。

`if hit is not None` 才算命中。`if hit` 会把缓存里的空字符串当成没有。

---

## 本课肌肉记忆

1. 命中就不再读库，所以旧键就是旧数据
2. 更新是删键，不是把新值写进缓存
3. `ex` 是兜底，不是这次失效的办法
