# 第 43 课：从 Controller 分发看何时不用 Agent

多数业务一句话就能决定去哪：查手册、改待办、或者只是打个招呼。这个 if 就是 Controller 的路径映射。先花一次模型调用让它「自己决定要不要当 Agent」，那一次已经在花钱，而且它可能选错。

运行：

```bash
PYTHONUTF8=1 python 43-何时不用Agent/43_取舍.py
```

| 用户句 | 路径 | 模型调用 |
|---|---|---|
| 退款几天 | 检索 | 0。走第 35 课的引用，手册没有也不会编 |
| 列出待办 | 工具 | 2。有上限的循环 |
| 你好 | 直接回答 | 1。不传 `tools` |
| TOOL:LOOP | 工具 | 3，然后 `步数用尽` |

---

## 1. 三条路径

```text
手册里的事实  → 检索。命中才回答，不命中就「不知道」。不要为了它启动工具循环
待办的读写    → 工具循环。步数有上限，参数不合法就拒绝
其它          → 一次普通对话，或者你根本不调模型
```

对照：`/notes` 不会进退款流程，`/refund` 也不会去建待办。路径是你映射的。模型适合填不确定的参数，不适合当总线路由器——至少在规则已经写得出来的时候不适合。

「退款几天」如果进了 Agent：空转几步，每步一份 token，最后仍可能编一个天数。第 37 课已经能 0 次模型调用回答它。

---

## 2. 贵在步数

一次检索 + 一次生成，是阶段七的形状，本课的检索甚至把生成也省了（回答用命中的原句）。
工具循环里，`列出待办` 是 2 次模型调用：一次要工单，一次写给人看。
`TOOL:LOOP` 会把这 2 变成 3，然后被 `max_steps` 截断。没有这行 `range`，它会一直要下去。

能写成一个普通函数调用的，就不要包成会自己转圈的 Agent。
