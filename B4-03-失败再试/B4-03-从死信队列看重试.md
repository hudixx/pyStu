# 选修 B4 第 3 课：从死信队列看重试

失败可以再做一次。次数用完还失败，就放到另一个列表里，不要再回到原队列。对照死信队列。一直重试的话，一笔坏消息会把后面的任务挡住。

本课不装 Celery，不启动工人进程，也不连真的 Redis。队列就是 `fakeredis` 里的一个 list。

运行：

```bash
PYTHONUTF8=1 python B4-03-失败再试/03_重试.py
```

应看到：

```text
会好的那笔
第1次 暂时失败
第2次 完成
死信 0
一直失败的那笔
第1次 暂时失败
第2次 暂时失败
死信 1 A-2
```

---

## 1. 怎么排队

`lpush` 从左边放，`rpop` 从右边拿。先放进去的先被处理。

`rpop` 发现列表是空的，立刻返回 `None`，循环结束。`brpop` 会停在那里等下一笔。这个文件里没有另一个人往队列里放，用 `brpop` 就停住了。

任务是 JSON 字符串。`attempt` 从 1 开始。失败并且还没到 2 次，就把 `attempt` 加 1，再 `lpush` 回 `jobs`。第 2 次仍失败，`lpush` 到 `dead`，不再回 `jobs`。

`llen` 对一个还没建过的键返回 `0`，不是 `None`。

同一笔消息仍可能被做两次：做完了、还没来得及从队列拿掉，进程就死了。下一课写怎么认出来「已经做过」。

## 本课肌肉记忆

1. 重试要有次数
2. 次数用完进死信，不回原队列
3. 本课用 `rpop`。`brpop` 会空等
